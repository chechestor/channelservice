# Обзор прототипа

Краткая выжимка из [полного ТЗ](tz.md). При расхождении приоритет у `tz.md`.

## Стек

- React + TypeScript + Vite
- CSS / CSS Modules (без тяжёлых UI-kit)
- Lucide Icons — допустимо
- Без backend, БД, внешних API, авторизации
- Состояние только в React state; данные — mock

Запуск: `npm install` → `npm run dev`  
Сборка: `npm run build`

## Один экран

**Заявки на выезд** — единственный основной экран.

Допустимы как состояния того же экрана: modal, drawer, dropdown, toast, confirmation.

Не делать: отдельные кабинеты, логин, CRM, карту, аналитику, настройки.

## Layout (desktop, ≥ 1280 px)

1. **Header** — «Каналсервис / Центр управления», заголовок экрана, селектор роли (Диспетчер / Руководитель / Бригадир).
2. **Таблица заявок** — 5–6 mock-заявок, фильтры-chips: Все / Аварийные / Требуют назначения / Назначенные.
3. **Drawer заявки** (≈ 450–550 px) — детали, блок назначения, история.

Стиль: внутренний business UI — спокойный, функциональный, без маркетинговой декоративности.

## Ядро UX

- Система **рекомендует** бригаду; последнее слово — у диспетчера.
- Автоподбор: loading 500–800 мс → рекомендация + альтернативы.
- Смена рекомендации → обязательный комментарий.
- Demo-меню: сброс, конфликт, «нет свободных бригад».

## Права (demo-роли)

| Роль | Назначение |
|------|------------|
| Диспетчер | полный цикл назначения |
| Руководитель | то же (+ опционально история) |
| Бригадир | только просмотр; назначение запрещено |

## Ключевые сущности

- **Request** — заявка (`unassigned` / `assigned` / …)
- **Crew** — бригада (`available` / `busy` / …), оборудование
- **Role** — `dispatcher` | `manager` | `crew_leader`
- История действий — в state drawer
