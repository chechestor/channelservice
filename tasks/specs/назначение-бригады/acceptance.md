# Acceptance Criteria

Источник: [tz.md](tz.md) §35–36.

Прототип готов, если выполняются все пункты:

| # | Критерий | Проверка |
|---|----------|----------|
| 1 | React-приложение запускается | `npm install && npm run dev` |
| 2 | Production build проходит | `npm run build` |
| 3 | Один основной экран «Заявки на выезд» | Визуально |
| 4 | Можно открыть заявку | Click → drawer |
| 5 | Можно запустить автоподбор | Click |
| 6 | Система предлагает бригаду | Рекомендация после подбора |
| 7 | Можно подтвердить назначение | Click |
| 8 | Статус таблицы обновляется | После назначения |
| 9 | Можно заменить рекомендацию | Click «Выбрать другую» |
| 10 | При замене обязателен комментарий | Без текста назначить нельзя |
| 11 | Можно показать конфликт | Demo scenario |
| 12 | Двойное назначение не создаётся | После конфликта — одна бригада |
| 13 | Можно показать недостаток прав | Роль «Бригадир» |
| 14 | При отказе в правах состояние не меняется | Проверка |
| 15 | Можно показать отсутствие бригады | Demo scenario |
| 16 | Есть reset | Данные в исходное состояние |
| 17 | Нет backend-зависимостей | Проверка проекта |

## Качество кода

- простой, читаемый, без overengineering;
- компоненты не чрезмерно крупные;
- TypeScript без `any`, где разумно;
- консоль без ошибок;
- нет TODO и незавершённых placeholder в финале.
